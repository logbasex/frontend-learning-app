Why server components, in 500 words

By Alice — 2026-05-02 — 5 min read

Some of your component tree runs on the server and never ships JavaScript to the browser. That is the whole idea of React Server Components. The browser receives the HTML those components produced, but never the components themselves.

The deal: the server pays one extra render hop, and the user pays nothing for that subtree's JavaScript. If the component reads data and renders it once, this is a clear win — the database query happens close to the data, the bundle never grows, and the user sees a faster first paint.

The cost: server components cannot use state, effects, or event handlers. The moment you need interactivity, you opt the relevant subtree into being a client component (`use client`). The boundary is one-way: a server component can render a client component, but not vice versa.
