# Concept Catalog

**Date:** 2026-05-09
**Status:** Authoritative shared vocabulary for all module authoring.

This catalog locks the canonical one-line definition of every term used across the curriculum. Authors **must** use the exact phrasing here when introducing a term. When a module references a term defined elsewhere, italicize the term on first use and link to the owning module.

Format: `Term — definition. (Owning module: <id>)`

## Phase 0 — Orientation

- **Source life** — The form of the app as files in the developer's editor: `.ts`, `.tsx`, `.css`, `.png`, `.env`. Not directly runnable in any browser. (Owning: `0-1`)
- **Built life (bundle)** — The form of the app after the build step: hashed JavaScript chunks, purged CSS, optimized assets, the `.next/` or `dist/` directory. This is what the CDN serves. (Owning: `0-1`)
- **Runtime life** — The form of the app while the user is using it: HTML in the document, JavaScript handlers attached to the DOM, requests in flight, state in React. (Owning: `0-1`)

## Phase 1 — Internet & Web Foundations

- **Internet** — A global network of networks that uses the IP protocol to deliver packets between machines. (Owning: `1-1`)
- **IP address** — A numeric address that identifies a machine on a network; v4 is dotted decimal (`93.184.216.34`), v6 is colon-hex. (Owning: `1-1`)
- **Packet** — A small chunk of data with a source/destination IP, sent independently across the network. (Owning: `1-1`)
- **DNS** — A directory that maps human-readable names to IP addresses. (Owning: `1-1`)
- **A record** — A DNS record that maps a name to an IPv4 address. (Owning: `1-1`)
- **AAAA record** — A DNS record that maps a name to an IPv6 address. (Owning: `1-1`)
- **CNAME record** — A DNS record that aliases one name to another name. (Owning: `1-3`)
- **TTL (DNS)** — The number of seconds a DNS record may be cached before it must be re-fetched. (Owning: `1-1`)
- **Recursive resolver** — A DNS server that walks the DNS tree on the client's behalf and caches results. (Owning: `1-1`)
- **Authoritative nameserver** — The DNS server that holds the original record for a domain. (Owning: `1-1`)
- **TCP** — A reliable, ordered, connection-oriented transport protocol that guarantees delivery and order via acknowledgments. (Owning: `1-1`)
- **UDP** — An unreliable, connectionless transport that fires packets and forgets — faster than TCP, no delivery guarantee. (Owning: `1-1`)
- **TCP three-way handshake** — SYN, SYN-ACK, ACK — one round-trip that establishes a TCP connection before any data flows. (Owning: `1-1`)
- **RTT (round-trip time)** — The time for a packet to travel to the server and a reply to come back. (Owning: `1-1`)
- **TLS** — A protocol layered on top of TCP that encrypts the channel and verifies the server's identity. (Owning: `1-1`, `1-2`)
- **TLS handshake** — The negotiation that exchanges cipher choice, server certificate, and key material; one extra RTT in TLS 1.3. (Owning: `1-1`, `1-2`)
- **Certificate (TLS)** — A signed document binding a public key to a domain name, issued by a Certificate Authority. (Owning: `1-2`)
- **Certificate Authority (CA)** — A trusted issuer of TLS certificates whose root keys are bundled in browsers and operating systems. (Owning: `1-2`)
- **HTTP** — The application-layer protocol for client-server requests and responses on the web. (Owning: `1-2`)
- **HTTPS** — HTTP carried over a TLS-encrypted TCP connection. (Owning: `1-2`)
- **HTTP method** — The verb in an HTTP request: GET, POST, PUT, PATCH, DELETE, HEAD, OPTIONS. (Owning: `1-2`)
- **HTTP status code** — A 3-digit response code: 1xx info, 2xx success, 3xx redirect, 4xx client error, 5xx server error. (Owning: `1-2`)
- **HTTP header** — A `Name: value` line of metadata sent with a request or response (e.g. `Content-Type`, `Cookie`). (Owning: `1-2`)
- **Idempotent** — A method whose result is the same whether called once or many times (GET, PUT, DELETE are idempotent; POST is not). (Owning: `1-2`)
- **Cookie** — A small key-value pair the server sends via `Set-Cookie` and the browser auto-attaches to subsequent requests. (Owning: `1-2`, `6-4`)
- **Cache (HTTP)** — A store that holds copies of responses and serves them without re-fetching when valid. (Owning: `1-2`)
- **CDN (Content Delivery Network)** — A globally distributed cache that serves static assets from a node geographically near the user. (Owning: `1-3`)
- **Domain name** — A human-readable name like `example.com`, structured as labels separated by dots. (Owning: `1-3`)
- **TLD (top-level domain)** — The right-most label of a domain (`.com`, `.sh`, `.org`). (Owning: `1-3`)
- **Hosting** — A service that runs your code/files on a machine reachable from the internet. (Owning: `1-3`)
- **Static hosting** — Hosting that serves pre-built files unchanged (no per-request server logic). (Owning: `1-3`)
- **Browser** — A program that fetches HTML/CSS/JS over HTTP and renders pixels. (Owning: `1-4`)
- **Rendering pipeline** — Parse HTML → DOM, parse CSS → CSSOM, combine into a render tree, layout, paint, composite. (Owning: `1-4`)
- **DOM (Document Object Model)** — The browser's in-memory tree representation of an HTML document. (Owning: `1-4`, `4-2`)
- **CSSOM** — The browser's in-memory tree of CSS rules, parallel to the DOM. (Owning: `1-4`)
- **Render tree** — The combined DOM + CSSOM tree containing only nodes that will be painted (no `display: none`). (Owning: `1-4`)
- **Layout (reflow)** — The browser computing geometry (positions and sizes) for every node in the render tree. (Owning: `1-4`)
- **Paint** — The browser turning render-tree nodes into pixels on layers. (Owning: `1-4`)
- **Composite** — The browser combining painted layers into the final image. (Owning: `1-4`)
- **Critical rendering path** — The sequence of steps from receiving HTML bytes to first paint. (Owning: `1-4`)

## Phase 2 — HTML

- **HTML** — A markup language whose elements describe the *meaning* of content; layout is CSS's job. (Owning: `2-1`)
- **Element (HTML)** — A tag pair with optional content and attributes (`<p class="lead">…</p>`). (Owning: `2-1`)
- **Tag** — The angle-bracketed opener or closer of an element (`<p>`, `</p>`). (Owning: `2-1`)
- **Attribute** — A `name="value"` pair on an opening tag (`class="lead"`). (Owning: `2-1`)
- **Semantic HTML** — Choosing elements that convey meaning (`<article>`, `<nav>`, `<main>`) over generic `<div>` and `<span>`. (Owning: `2-1`)
- **Document outline** — The implicit hierarchy of headings (`<h1>`–`<h6>`) that screen readers and search engines parse. (Owning: `2-1`)
- **Form** — An `<form>` element wrapping inputs that submit data via HTTP. (Owning: `2-2`)
- **Input** — An `<input>`, `<textarea>`, or `<select>` element that captures user data. (Owning: `2-2`)
- **Label association** — Connecting an `<input>` to a `<label>` via `for=id`, wrapping, or `aria-labelledby` so screen readers announce the field's name. (Owning: `2-2`)
- **Native form validation** — Browser-built validation triggered by `required`, `pattern`, `type="email"`, etc. (Owning: `2-2`)
- **Accessibility (a11y)** — Designing so every user — including users of screen readers, keyboards, and non-pointer devices — can use the page. (Owning: `2-3`)
- **WCAG** — Web Content Accessibility Guidelines; AA is the practical baseline. (Owning: `2-3`)
- **ARIA** — Attributes that add accessibility metadata (`role`, `aria-label`) when the chosen HTML element can't express it. First rule: don't use ARIA if a semantic element does the job. (Owning: `2-3`)
- **Focus order** — The sequence in which keyboard `Tab` moves through interactive elements; should match visual reading order. (Owning: `2-3`)
- **SEO** — Search engine optimization — practices that help search engines understand and rank a page. (Owning: `2-4`)
- **Meta tag** — A `<meta>` element in `<head>` carrying metadata for browsers, crawlers, and social platforms. (Owning: `2-4`)
- **Open Graph** — A meta-tag standard (`og:title`, `og:image`) used by social platforms to render link previews. (Owning: `2-4`)
- **Sitemap** — An XML file at `/sitemap.xml` listing the site's URLs for crawlers. (Owning: `2-4`)
- **robots.txt** — A file at `/robots.txt` telling crawlers which paths to index or skip. (Owning: `2-4`)

## Phase 3 — CSS

- **CSS** — A stylesheet language for matching elements with selectors and assigning property values. (Owning: `3-1`)
- **Selector** — A pattern that matches elements (`.button`, `nav > a`, `[type="email"]`). (Owning: `3-1`)
- **Property** — A styling attribute (`color`, `padding`, `display`). (Owning: `3-1`)
- **Cascade** — The CSS algorithm that resolves which rule wins when multiple match the same element. (Owning: `3-1`)
- **Specificity** — The score that ranks colliding CSS rules: inline > ID > class/attr/pseudo-class > element. (Owning: `3-1`)
- **Inheritance (CSS)** — Some properties (e.g. `color`, `font-size`) propagate from parent to child unless overridden. (Owning: `3-1`)
- **Box model** — Every element is a rectangle of `content + padding + border + margin`. (Owning: `3-1`)
- **`box-sizing: border-box`** — A box-sizing mode that includes padding and border inside the declared width — the modern default. (Owning: `3-1`)
- **Block element** — An element that takes a full row by default (`<div>`, `<p>`, `<section>`). (Owning: `3-1`)
- **Inline element** — An element that flows alongside text (`<span>`, `<a>`, `<em>`). (Owning: `3-1`)
- **Flexbox** — A 1-D layout system that distributes space along a single axis (row or column). (Owning: `3-2`)
- **Grid** — A 2-D layout system that divides space into rows and columns simultaneously. (Owning: `3-2`)
- **Main axis / cross axis** — In Flexbox, the axis the items are laid along (main) and perpendicular to it (cross). (Owning: `3-2`)
- **`fr` unit** — A unit in Grid representing a fraction of remaining space. (Owning: `3-2`)
- **Media query** — A `@media (...)` block that applies styles only when the viewport matches. (Owning: `3-3`)
- **Mobile-first** — Authoring base styles for narrow viewports, then layering wider-viewport overrides via `min-width` queries. (Owning: `3-3`)
- **Container query** — A `@container` query that styles based on a *parent's* size, not the viewport. (Owning: `3-3`)
- **`clamp()`** — A CSS function `clamp(min, preferred, max)` that produces a value bounded by min/max. (Owning: `3-3`)
- **Tailwind CSS** — A utility-first CSS framework: small, single-purpose classes (`.flex`, `.p-4`, `.text-blue-500`) composed inline. (Owning: `3-4`)
- **Utility class** — A class that does one thing (`.flex` sets `display: flex`); composed inline rather than building bespoke CSS. (Owning: `3-4`)
- **CSS Modules** — A build-time CSS-scoping technique that hashes class names so styles can't leak. (Owning: `3-4`)
- **CSS-in-JS** — Writing CSS as JavaScript objects or template literals; runtime variants inject styles at render time. (Owning: `3-4`)
- **BEM** — A class-naming convention `Block__Element--Modifier` for keeping CSS scoped without tooling. (Owning: `3-5`)
- **Sass** — A CSS preprocessor adding nesting, variables, mixins, and functions; compiles to CSS. (Owning: `3-5`)
- **PostCSS** — A CSS post-processor that transforms CSS via plugins (autoprefixer, modern-syntax compilers). (Owning: `3-5`)

## Phase 4 — JavaScript

- **JavaScript** — A single-threaded, dynamically typed language that runs in the browser and on Node.js. (Owning: `4-1`)
- **Primitive** — A simple value type: string, number, boolean, null, undefined, symbol, bigint. Copied by value. (Owning: `4-1`)
- **Reference type** — Object, array, function. Copied by reference. (Owning: `4-1`)
- **Scope** — The region of code where a binding (variable) is visible. (Owning: `4-1`)
- **Block scope** — A scope created by `{ ... }`; `let` and `const` are block-scoped. (Owning: `4-1`)
- **Hoisting** — `var` declarations and `function` statements are visible from the top of their scope; `let`/`const` are not. (Owning: `4-1`)
- **Closure** — A function plus the variable bindings of where it was defined. (Owning: `4-1`)
- **`this`** — A binding set by the call site, not the declaration; arrow functions capture lexical `this`. (Owning: `4-1`)
- **Prototype** — The object an object inherits from; the chain ends at `null`. (Owning: `4-1`)
- **DOM API** — The set of methods for querying and mutating the DOM (`document.querySelector`, `element.appendChild`). (Owning: `4-2`)
- **Event** — A notification dispatched on a target element when something happens (click, keypress, load). (Owning: `4-2`)
- **Event listener** — A function registered with `addEventListener` to run when an event fires. (Owning: `4-2`)
- **Event bubbling** — An event fires on the target, then on each ancestor up to the document. (Owning: `4-2`)
- **Event delegation** — Listening on a parent and using `event.target` to dispatch to the relevant child. (Owning: `4-2`)
- **Event loop** — The runtime mechanism that pulls tasks off the queue and runs them on the single thread. (Owning: `4-2`)
- **Call stack** — The active function-call frames; pushed on call, popped on return. (Owning: `4-2`)
- **Macrotask** — A unit of work scheduled via `setTimeout`, I/O, or rendering; one runs per event-loop turn. (Owning: `4-2`)
- **Microtask** — A unit of work scheduled via promise resolution; the queue drains fully between macrotasks. (Owning: `4-2`)
- **Promise** — An object representing a value that may be available now, later, or never. (Owning: `4-3`)
- **`async` / `await`** — Syntax sugar over Promises: `await` pauses an `async` function until the Promise settles. (Owning: `4-3`)
- **`fetch()`** — The modern browser API for making HTTP requests; returns a Promise resolving to a `Response`. (Owning: `4-3`)
- **AbortController** — A pair `{ signal, abort() }` used to cancel an in-flight `fetch`. (Owning: `4-3`)

## Phase 5 — Workflow & Frameworks

- **Git** — A distributed version control system that tracks snapshots of files. (Owning: `5-1`)
- **Commit** — A snapshot of the working tree plus a message; addressed by SHA-1. (Owning: `5-1`)
- **Branch** — A movable pointer to a commit. (Owning: `5-1`)
- **Merge** — Combining two branches by creating a merge commit with two parents. (Owning: `5-1`)
- **Rebase** — Replaying one branch's commits on top of another, rewriting history. (Owning: `5-1`)
- **Pull request** — A GitHub workflow for proposing a branch's changes for review and merge. (Owning: `5-1`)
- **package.json** — The manifest that declares a project's dependencies and scripts. (Owning: `5-2`)
- **Lockfile** — The resolved, exact dependency graph (`pnpm-lock.yaml`, `package-lock.json`). (Owning: `5-2`)
- **Semver** — Versioning scheme `major.minor.patch` — break, add, fix. (Owning: `5-2`)
- **pnpm** — A package manager that uses a content-addressed store and symlinks for fast installs and small disk usage. (Owning: `5-2`)
- **Workspace (monorepo)** — A root `package.json` orchestrating multiple sub-packages in one repo. (Owning: `5-2`)
- **React** — A library for building UIs as a function of state, expressed as components that return tree-shaped descriptions. (Owning: `5-3`)
- **Component (React)** — A function returning JSX (a description of UI for a given props/state). (Owning: `5-3`)
- **JSX** — A syntax extension that lets you write HTML-like markup inside JavaScript; compiled to function calls. (Owning: `5-3`)
- **Props** — Inputs to a component, passed as a single object argument. (Owning: `5-3`)
- **State (React)** — Values a component owns and may change; React re-renders when state changes. (Owning: `5-3`)
- **Hook** — A function whose name starts with `use` that lets a component opt into React features (`useState`, `useEffect`, `useMemo`). (Owning: `5-3`)
- **Render (React)** — Calling a component with current props/state to produce a JSX tree. (Owning: `5-3`)
- **Reconciliation** — React diffing the new JSX tree against the previous one and applying minimal DOM changes. (Owning: `5-3`)
- **Effect** — Code declared with `useEffect` that runs after render to sync with non-React systems. (Owning: `5-3`)
- **TypeScript** — A typed superset of JavaScript that adds static type checking; compiles to JS. (Owning: `5-4`)
- **Type** — A description of the shape of a value (`string`, `User`, `(id: number) => Promise<User>`). (Owning: `5-4`)
- **Structural typing** — Two types are compatible if their shapes match, regardless of name. (Owning: `5-4`)
- **Narrowing** — Using control-flow checks (`typeof`, `in`, `===`) to refine a union type to a single arm. (Owning: `5-4`)
- **Generic** — A type parameterized by another type (`Array<T>`, `Promise<T>`). (Owning: `5-4`)

## Phase 6 — Build, Test & Secure

- **Linter** — A tool that statically analyzes code for likely bugs and style issues (ESLint). (Owning: `6-1`)
- **Formatter** — A tool that rewrites code into a canonical layout (Prettier). (Owning: `6-1`)
- **Pre-commit hook** — A Git hook that runs before a commit; commonly runs lint/format. (Owning: `6-1`)
- **Bundler** — A tool that combines source modules into deliverable assets for the browser. (Owning: `6-2`)
- **Vite** — A modern dev server + bundler: serves source as native ES modules in dev, bundles with Rollup for production. (Owning: `6-2`)
- **Hot Module Replacement (HMR)** — Updating a module in the running page without a full reload, preserving state. (Owning: `6-2`)
- **Tree-shaking** — Eliminating unused exports during bundling. (Owning: `6-2`)
- **Code splitting** — Splitting the bundle into chunks loaded on demand. (Owning: `6-2`)
- **Vitest** — A Vite-native unit/component test runner with Jest-compatible API. (Owning: `6-3`)
- **Playwright** — An end-to-end browser-automation test framework. (Owning: `6-3`)
- **Test pyramid** — Many fast unit tests, fewer integration tests, fewest E2E tests. (Owning: `6-3`)
- **Authentication** — Verifying *who* the user is. (Owning: `6-4`)
- **Authorization** — Deciding *what* an authenticated user is allowed to do. (Owning: `6-4`)
- **JWT** — A signed (not encrypted by default) token carrying claims as a base64-encoded JSON header.payload.signature. (Owning: `6-4`)
- **Session cookie** — A cookie holding an opaque session ID; the server stores the actual session data. (Owning: `6-4`)
- **OAuth 2.0** — A delegation protocol where a third party gets permission to act on a user's behalf without seeing their password. (Owning: `6-4`)
- **PKCE** — Proof Key for Code Exchange — an OAuth extension that protects public clients (browsers, mobile) from authorization-code interception. (Owning: `6-4`)
- **Same-origin policy** — A browser rule that prevents a page from reading another origin's data unless explicitly allowed. (Owning: `6-5`)
- **CORS** — A browser mechanism by which a server opts in to cross-origin reads via response headers. (Owning: `6-5`)
- **XSS (Cross-Site Scripting)** — Attacker-controlled JavaScript executing in your origin. (Owning: `6-5`)
- **CSRF (Cross-Site Request Forgery)** — An attacker's site triggering an authenticated request from the victim's browser. (Owning: `6-5`)
- **CSP (Content Security Policy)** — An HTTP header allow-listing which sources of code/styles/images may execute or load. (Owning: `6-5`)

## Phase 7 — Beyond the Browser & Production

- **Web Component** — A platform-native custom element with optional Shadow DOM and template; framework-agnostic. (Owning: `7-1`)
- **Custom Element** — A class extending `HTMLElement` and registered via `customElements.define()`. (Owning: `7-1`)
- **Shadow DOM** — A subtree attached to an element whose styles and IDs are encapsulated from the outer document. (Owning: `7-1`)
- **`<template>`** — An inert HTML fragment that the browser does not render until cloned and inserted. (Owning: `7-1`)
- **Slot** — A `<slot>` element inside a Web Component template that fills with light-DOM children projected by the host. (Owning: `7-1`)
- **CSR (Client-Side Rendering)** — The page is delivered as near-empty HTML; JavaScript fetches data and renders in the browser. (Owning: `7-2`)
- **SSR (Server-Side Rendering)** — The server renders HTML for each request; the browser receives a fully-formed document. (Owning: `7-2`)
- **SSG (Static Site Generation)** — Pages are pre-rendered at build time and served as static HTML. (Owning: `7-2`, `7-4`)
- **ISR (Incremental Static Regeneration)** — SSG with revalidation: pages re-build on demand after a TTL. (Owning: `7-2`)
- **Hydration** — Attaching client-side React (or framework) to server-rendered HTML so it becomes interactive. (Owning: `7-2`)
- **RSC (React Server Components)** — Components rendered on the server only; their JavaScript is never shipped to the client. (Owning: `7-2`)
- **Next.js** — A React meta-framework providing routing, SSR/SSG/ISR/RSC, and an opinionated build pipeline. (Owning: `7-2`)
- **GraphQL** — A query language for APIs where the client specifies the exact shape of the response. (Owning: `7-3`)
- **Schema (GraphQL)** — The contract that defines available types, queries, mutations, and subscriptions. (Owning: `7-3`)
- **Resolver** — A function that produces the value for a single field in a GraphQL query. (Owning: `7-3`)
- **Apollo Client** — A popular GraphQL client with normalized caching by id. (Owning: `7-3`)
- **Astro** — An island-architecture SSG that ships HTML by default and JavaScript only for interactive components. (Owning: `7-4`)
- **Eleventy (11ty)** — A simple, JavaScript-based SSG. (Owning: `7-4`)
- **Islands architecture** — A page is mostly static HTML with isolated interactive components ("islands") that ship JS independently. (Owning: `7-4`)
- **PWA (Progressive Web App)** — A web app that's installable, offline-capable, and behaves like a native app via service workers. (Owning: `7-5`)
- **Service worker** — A scriptable proxy between the browser and the network, used for caching, push, offline. (Owning: `7-5`)
- **Cache API** — The browser API for storing `Request`/`Response` pairs, typically used by service workers. (Owning: `7-5`)
- **IndexedDB** — A browser-native NoSQL database for structured client-side storage. (Owning: `7-5`)
- **WebSocket** — A persistent, bidirectional connection layered on a single TCP connection, used for real-time messaging. (Owning: `7-5`)
- **Server-Sent Events (SSE)** — A one-way streaming protocol from server to client over HTTP. (Owning: `7-5`)
- **React Native** — A framework that uses React to render real platform-native UI on iOS and Android via a JS bridge. (Owning: `7-6`)
- **Flutter** — A Google framework using Dart and its own renderer; every pixel is drawn by Flutter. (Owning: `7-6`)
- **Ionic** — A web-tech mobile framework that runs the UI inside a native WebView via Capacitor. (Owning: `7-6`)
- **Electron** — A desktop framework bundling Chromium + Node into a self-contained app. (Owning: `7-7`)
- **Tauri** — A desktop framework using the OS-native webview + a Rust backend; smaller and more secure than Electron. (Owning: `7-7`)
- **Core Web Vitals** — Google's three top-line UX metrics: LCP (loading), INP (interaction), CLS (layout stability). (Owning: `7-8`)
- **LCP (Largest Contentful Paint)** — Time from navigation start to the largest visible content element being painted. (Owning: `7-8`)
- **INP (Interaction to Next Paint)** — The slowest interaction's delay-to-visual-update during the page lifetime. (Owning: `7-8`)
- **CLS (Cumulative Layout Shift)** — A unitless score of how much elements jumped while the page was loading. (Owning: `7-8`)
- **Lighthouse** — A Google tool that audits a page for performance, accessibility, SEO, and best practices. (Owning: `7-8`)
- **PRPL** — A delivery pattern: Push critical resources, Render initial route, Pre-cache remaining routes, Lazy-load on demand. (Owning: `7-8`)
- **RAIL** — A performance budget by interaction kind: Response < 100ms, Animation 16ms/frame, Idle 50ms chunks, Load < 1s key content. (Owning: `7-8`)

## Phase 8 — Capstone (How a Modern Frontend App Works)

- **Module graph** — The directed graph of all imports the bundler walks to discover what to ship; entry → imports → imports' imports → leaves. (Owning: `8-1`)
- **Bundle** — The output of running the build: the set of files the CDN serves to a browser. Distinct from the source. (Owning: `8-1`)
- **Chunk** — A single JavaScript file in the bundle, produced by code-splitting the module graph along route or dynamic-import boundaries. (Owning: `8-1`)
- **Tree-shaking** — The bundler's removal of exports the module graph never reaches. Requires ESM and side-effect-free modules to work. (Owning: `8-1`)
- **Hydration mismatch** — When the HTML produced on the server differs from what React renders on the client at hydration time. Causes a visible flash and a console error. (Owning: `8-2`)
- **Server component** — A React component that runs only on the server (or at build time) and ships zero JavaScript to the browser. Default in the Next.js App Router. (Owning: `8-3`)
- **Client component** — A React component opted into running in the browser via `"use client"`. Hydrated and interactive. (Owning: `8-3`)
- **Server action** — A function annotated `"use server"` that runs on the server and is callable from the client like a remote procedure. The form-submission shape that replaces hand-written `fetch` calls. (Owning: `8-3`)
- **Optimistic UI** — Updating the UI to reflect a user's action before the server confirms it; reconciling on response. Makes interactions feel instant at the cost of handling rollback. (Owning: `8-3`)
- **Prefetch** — The framework fetching a route's code or data ahead of an explicit navigation, usually on hover or visibility, so the actual click resolves instantly. (Owning: `8-2`)

## Author rules

- **Use the exact phrasing.** When introducing a term in its owning module, state it as the catalog has it. Do not paraphrase.
- **Italicize on first cross-module use.** When a term defined in module X appears in module Y, italicize the term *and* link to module X by ID — `*DNS* (defined in module 1-1)`.
- **Add to the catalog when needed.** If authoring reveals a missing term, add it here in a follow-up edit before the module ships. Do not invent a competing definition in a module.
- **Catalog is single source of truth.** A term's definition lives here, full stop. If a definition needs to change, change it here and audit every reference.
